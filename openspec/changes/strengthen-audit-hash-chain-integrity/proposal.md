# Change: 强化审计哈希链追加与全量校验

## Why

操作审计哈希链用于发现记录篡改，但当前服务层通过 `list()` 推断上一条事件，而 MySQL `list()` 只返回最近 500 条且按倒序排列。随着审计数据增长，完整性校验可能只覆盖窗口数据，追加链也会与查询分页语义耦合。并发写入时，多个请求还可能在同一进程内读取到相同上一哈希。

## What Changes

- 审计仓储新增 `latest()`，用于追加事件时获取真实最新哈希。
- 审计仓储新增 `listForIntegrity()`，按写入顺序返回完整校验数据。
- MySQL `list()` 保留最近 500 条倒序查询，`listForIntegrity()` 改为全量正序。
- 内存审计仓储加互斥，服务层 `record()` 加互斥，降低同进程并发分叉风险。
- 基础测试确认查询仍为最新优先，完整性校验仍验证全链。

## Non-Goals

- 不在本模块引入跨进程数据库锁或分布式事务。
- 不改变审计事件字段结构、哈希算法或 HTTP API 响应格式。
- 不改变审计查询接口的最近优先展示语义。
