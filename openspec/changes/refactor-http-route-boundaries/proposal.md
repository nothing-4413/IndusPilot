# Change: 重构 HTTP 模块边界

## Why

当前 Drogon HTTP 实现集中在单个约 1600 行的源文件中，同时承担路由注册、请求解析、响应序列化、认证授权、审计指标、仓储创建和服务组装。现有业务服务已经具备独立边界，但后续模块仍必须修改中央 HTTP 文件，增加了接入冲突和回归风险。

## What Changes

- 将 HTTP 公共能力与业务路由注册拆分为独立模块。
- 为每个现有业务上下文提供独立的 route registrar。
- 将仓储、会话和业务服务创建收敛到明确的 composition root。
- 保持现有 API 路径、HTTP 方法、权限、响应结构和 HTTP smoke 行为兼容。
- 为后续模块定义可复制的 HTTP 接入边界和测试入口。

## Non-Goals

- 本次不新增业务 API。
- 本次不改变认证模型、权限名称或持久化协议。
- 本次不引入动态插件加载或运行时模块发现。
- 本次不实现 readiness/startup 语义；该内容由后续独立 change 处理。
